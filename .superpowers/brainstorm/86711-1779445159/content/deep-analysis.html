深入分析：业务逻辑的线性与冲突

检查后端数据模型后发现 3 个潜在问题

数据关系：一个表单 → 多条记录

表单 D001（电梯查验）
  ├─ 记录 #1：1栋 101室  2024-01-15  ✅ 合格
  ├─ 记录 #2：1栋 102室  2024-01-15  ⚠️ 2项不合格
  ├─ 记录 #3：2栋 201室  2024-01-16  ✅ 合格
  └─ 记录 #4：1栋 101室  2024-02-01  ✅ 复验合格  ← 和记录#1同一位置!

一个表单检查多处位置是正常的。但同一位置被同一表单检查多次（如记录#1和#4），目前系统没有任何拦截，会无限制创建重复记录。

🔴 问题 A：无重复记录拦截

数据库层面：inspection_records 表没有唯一约束。同一个 form + 同一个 building + 同一个 house 可以创建无限条记录。

风险：用户可能不小心对同一位置重复录入，数据混乱。

🔴 问题 B：修改表单会影响已有记录的显示

当前机制：记录的检查项名称是通过外键 JOIN 到表单实时查询的，不是快照。

举例：

1. 表单 D001 第5项叫「电梯门锁装置」→ 创建记录，录入结果
2. 后来编辑表单，把第5项改成「电梯门锁安全装置」
3. 回看老记录 → 显示的是「电梯门锁安全装置」（因为实时JOIN查询）
→ 历史记录被改了！不符合审计要求

🔴 问题 C：复验场景怎么处理？

如果第一次检查发现不合格项，维修后需要复验：

  • 方案1：在原记录上修改结果（覆盖历史，不符合审计）
  • 方案2：新建一条记录（目前可行，但没有标记"这是复验"）
  • 方案3：在原记录上追加复验结果（需要新功能）

需要你决策的 3 个问题

Q1：同一位置能否用同一表单多次检查？

比如 1栋101室 + D001电梯表单，检查了一次后还能不能再建？

A

允许重复，不拦截

复验场景需要新建记录，由操作人员自己判断。保持灵活性。

B

弹窗提示，但允许继续

"该位置已有检查记录（2024-01-15，查验人张三），是否创建新记录？"

C

禁止重复，强制在原记录上修改

同一表单+同一位置只能有一条记录，复验直接改原记录

Q2：编辑表单后，已有记录显示什么？

改了表单的检查项名称或增删项目，老记录怎么显示？

A

记录创建时保存快照，不受后续表单修改影响

记录创建时把检查项名称固化，之后改表单不影响老记录（推荐，符合审计）

B

保持现状，实时引用表单最新值

改表单后老记录跟着变。不推荐，但实现简单。

C

一旦有记录产生，表单锁定不可编辑

只要有用这个表单创建的记录，表单就不能再改。想改得复制一份新表单。

Q3：复验（不合格项整改后重新检查）怎么处理？

第一次检查2项不合格 → 维修 → 再次检查这2项

A

新建整条记录

重新检查全部项目，生成新记录。旧记录保留作为历史。

B

在原记录上追加复验结果

不新建记录，在原记录的不合格项上加"复验结果"字段。（改动大）

C

先保持简单，直接修改原记录

现阶段不需要复验流程，检查员直接改结果就行。后续再考虑。
